# 📊 전처리 전후 결과 비교 보고서

## 1. 텍스트 정규화 (Text Normalization) 전후 비교
사용자 입력이나 원본 CSV 파일에 포함될 수 있는 불필요한 공백과 구두점을 정제하여 모델 입력 품질을 높인 결과입니다.

| 구분 | 전처리 전 (Before: 원본 상태) | 전처리 후 (After: `normalize_korean` 적용) | 비교 및 개선 효과 |
| :--- | :--- | :--- | :--- |
| **공백 압축** | `안녕하세요??      감사합니다!` <br>*(불필요한 연속 띄어쓰기 및 탭 공백 혼재)* | `안녕하세요? 감사합니다!` <br>*(중복 공백이 단일 공백 ` `으로 정돈됨)* | • **발음 지연 방지**: Edge-TTS가 문장을 읽을 때 공백 구간에서 어색하게 멈추거나 텀이 발생하는 현상을 원천 차단합니다. |
| **양끝 공백** | `   화장실 어디에 있어요?   ` <br>*(문장 앞뒤로 불필요한 여백 포함)* | `화장실 어디에 있어요?` <br>*( `strip()` 함수로 양끝 공백 완벽 제거)* | • **데이터 무결성 확보**: DB 적재 시 발생할 수 있는 보이지 않는 공백 에러를 막고, UI 출력의 깔끔함을 유지합니다. |
| **구두점 관리** | `서울역으로 가는 지하철은 어디서 타요??` <br>*(중복된 물음표/느낌표 등 제각각 부호)* | `서울역으로 가는 지하철은 어디서 타요?` <br>*(핵심 문장부호 `?`, `!`, `.` 안전하게 표준화 유지)* | • **STT 평가 오차 감소**: 음성 인식(STT) 및 평가(WER/CER) 시 텍스트 불일치로 인한 오인식률을 낮춰 객관적인 지표를 확보합니다. |
| **카테고리** | 무작위 순서 또는 데이터베이스 로드 순서 | `desired_order` 학습 단계 순서 고정 | • **UI 직관성 향상**: Streamlit 셀렉박스 및 학습 흐름이 사용자가 공부하기 가장 좋은 순서로 정렬됩니다. |

> 텍스트 정규화 단계에서는 원본 데이터의 불필요한 연속 공백과 양끝 여백을 정규식과 `strip()`으로 압축 및 정제했습니다. 이를 통해 Edge-TTS가 부자연스러운 침묵 없이 매끄러운 음성을 생성하도록 돕고, 최종 STT 평가 과정에서 텍스트 오차로 인한 왜곡을 방지하여 데이터 신뢰성을 높였습니다.

## 2. 오디오 신호 및 파이프라인 처리 전후 비교
생성된 음성 데이터를 STT 모델 평가 및 분석에 최적화된 표준 규격으로 변환하는 과정의 비교입니다.

| 구분 | 전처리 전 (Before: TTS 직후 상태) | 전처리 후 (After: `librosa` & `soundfile` 적용) | 비교 및 개선 효과 |
| :--- | :--- | :--- | :--- |
| **오디오 포맷** | 가변 샘플레이트의 압축 파일 (예: MP3 형식) | **16kHz, 모노(Mono), 16-bit PCM WAV** 표준 파일 | • **규격 일치**: STT 모델 추론 및 WER/CER 계산 모듈의 입력 요구사항을 충족하여 포맷 에러를 예방합니다. |
| **예외 핸들링** | CSV 파일 유실 시 프로그램 강제 종료(Crash) | DB 자동 폴백(Fallback) 조회 기능 연동 (`get_sentences_grouped`) | • **시스템 안정성**: 파일 유실 등 예외 상황에서도 중단 없이 DB 데이터를 안전하게 로드하여 서비스 가용성을 확보합니다. |

> 오디오 파이프라인 단계에서는 Edge-TTS가 생성한 원본 음성을 `librosa`와 `soundfile`을 통해 16kHz 모노 WAV 표준 규격으로 일괄 변환했습니다. 이를 통해 후속 STT 모델 추론 및 WER/CER 평가 과정에서 발생할 수 있는 포맷 충돌을 원천 차단하고, 시스템 전반의 처리 안정성을 높였습니다.
